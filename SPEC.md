# Спецификация: приложение для назначения лечения при кожных заболеваниях

## 1. Назначение

Веб-приложение для врача-дерматолога. Врач ведёт картотеку пациентов, рассчитывает
и назначает схему лечения препаратом и уход за кожей. Пациент по персональной
ссылке видит текущую неделю лечения (какую дозировку принимать сейчас) и
текущий список рекомендаций по уходу за кожей.

## 2. Пользователи

- **Врач** — на старте один пользователь (сам разработчик/владелец), архитектура
  должна допускать расширение на нескольких врачей/клинику в будущем без
  переписывания модели данных (у каждой записи пациента должен быть `doctor_id`).
- **Пациент** — доступ без регистрации и пароля, по уникальной непредсказуемой
  ссылке/токену вида `/patient/{token}`. Доступ только к своей карточке.

## 3. Стек

- **Frontend**: React + Vite, роутинг по ролям (`/doctor/*`, `/patient/:token`)
- **Backend-as-a-service**: Supabase
  - Postgres — данные пациентов, диагнозов, назначений, схем ухода
  - Storage — фото пациентов (например, для отслеживания динамики кожи)
  - Row Level Security — пациент видит только свою запись по токену; врач видит
    только своих пациентов (`doctor_id`)
- **Хостинг фронтенда**: репозиторий на GitHub, деплой на GitHub Pages
  (Vercel не используем — частично заблокирован в РФ, риск нестабильного
  доступа для пациентов)
- **Экспорт данных**: выгрузка таблиц в Excel/CSV — либо через встроенный экспорт
  Supabase, либо кнопкой в интерфейсе врача (SheetJS)

## 4. Модель данных (черновая)

### `doctors`
- id, name, email

### `patients`
- id, doctor_id, full_name, дата рождения, контактные данные
- вес (кг) — вводится один раз в карточке пациента; используется по
  умолчанию в калькуляторе дозировки и при расчёте назначения, с
  возможностью разовой ручной корректировки на конкретном расчёте
- access_token (уникальный, непредсказуемый — для ссылки пациента)
- дата создания карточки

### `diagnoses` (история болезни пациента)
- id, patient_id, тип патологии/диагноз, дата постановки, заметки врача

### `drugs` (справочник препаратов)
- id, doctor_id, название препарата

### `dosage_schemes` (схемы дозирования препарата)
- id, drug_id, название схемы (произвольное, придумывает врач — например
  «стандартная», «щадящая для подростков»), суточная доза на кг веса
  (мг/кг/сутки, одно значение, без диапазона)
- у препарата может быть сколько угодно схем; название и значение
  редактируются в любой момент — переименование схемы не затрагивает уже
  созданные на её основе назначения (они хранят ссылку на схему через
  `prescriptions.dosage_scheme_id`, а фактическую дозировку — фиксированной
  в момент расчёта, как и раньше)
- если схему удаляют, у назначений, созданных на её основе, ссылка на схему
  обнуляется, но сами назначения и их дозировки не удаляются

### `cumulative_dose_options` (справочные варианты кумулятивной дозы препарата)
- id, drug_id, название варианта (произвольное — например «короткий курс»,
  «стандартный курс»), кумулятивная доза на весь курс (мг/кг)
- у препарата может быть сколько угодно вариантов; каждый добавляется,
  редактируется и удаляется независимо
- это справочные цифры для ориентира при расчёте длительности курса — они
  **не привязаны** к конкретной схеме дозирования и **не блокируют**
  создание назначения при их превышении, только показываются рядом для
  сверки в калькуляторе и форме назначения

### `release_forms` (формы выпуска препарата)
- id, drug_id, форма выпуска (например "капсула 8 мг", "мазь"), доза одной
  единицы (мг), количество единиц в упаковке (шт)
- у одного препарата может быть несколько форм выпуска (например, Акнекутан —
  капсулы 8 мг и капсулы 16 мг)

### `prescriptions` (назначения — расчёт лечения препаратом)
- id, patient_id, diagnosis_id, drug_id, dosage_scheme_id
- вес пациента — выбирается в карточке пациента
- итоговая дозировка — рассчитывается автоматически (вес × мг/кг выбранной
  схемы дозирования), с возможностью ручной корректировки врачом; значение
  фиксируется на момент расчёта и не пересчитывается, даже если схему потом
  переименуют, изменят или удалят
- схема по неделям (JSON или отдельная таблица `prescription_weeks`)
- дата начала лечения, статус (активно/завершено)
- степень тяжести отдельным полем не хранится — при необходимости врач
  фиксирует её в свободных заметках (например, в истории болезни)

### `prescription_weeks`
- id, prescription_id, номер недели, дозировка на эту неделю, комментарий

### `skincare_routines` (уход за кожей)
- id, patient_id, средство/процедура, инструкция по применению, дата создания
- простой список записей ухода на пациента, без привязки к неделе лечения
  или к конкретному назначению препарата — врач добавляет, редактирует и
  удаляет записи в любой момент, пациент всегда видит текущий список целиком

### `patient_photos`
- id, patient_id, url (Supabase Storage), дата загрузки, заметка (например "неделя 3")
- uploaded_by (врач/пациент) — определяет права на редактирование/удаление

### `notifications`
- id, patient_id, получатель (врач/пациент), тип (заметка/назначение препарата/
  уход/фото), текст, дата создания, прочитано (да/нет)

## 5. Функциональность — интерфейс врача

- Справочник препаратов, схем дозирования и вариантов кумулятивной дозы:
  - врач заводит препарат и добавляет к нему произвольное количество именованных
    схем дозирования (например: «стандартная» — 4 мг/кг/сутки, «щадящая для
    подростков» — 2 мг/кг/сутки) — у каждой схемы одно значение суточной дозы
    на кг веса, без диапазона
  - схемы редактируются централизованно (название и значение), включая
    переименование без потери связи с уже созданными на их основе
    назначениями; изменение схемы не затрагивает уже рассчитанные ранее
    назначения (дозировка фиксируется в `prescriptions` на момент расчёта)
  - для препарата отдельно задаётся произвольное количество именованных
    вариантов кумулятивной (курсовой) дозы (например: «короткий курс» —
    60 мг/кг, «стандартный курс» — 120 мг/кг) — добавляются, редактируются и
    удаляются независимо друг от друга и от схем дозирования; это справочные
    цифры для ориентира при расчёте длительности курса, они не блокируют
    создание назначения при превышении
  - у препарата задаются одна или несколько форм выпуска (форма, доза за
    единицу в мг, количество единиц в упаковке) — редактируются в карточке
    препарата (добавление/редактирование/удаление)
- Картотека пациентов: список, поиск, фильтр по патологии/статусу лечения
- Карточка пациента:
  - История болезни (диагнозы, специализированные под кожные заболевания)
  - Текущее и прошлые назначения
  - Форма расчёта нового назначения: врач выбирает препарат и схему
    дозирования (вместо степени тяжести — степень тяжести при необходимости
    фиксируется в свободных заметках истории болезни); вес пациента
    подставляется автоматически из карточки пациента (без повторного ввода
    при каждом назначении), с возможностью разовой ручной корректировки,
    если вес изменился с последнего визита; форма показывает мг/кг/сутки
    выбранной схемы, и итоговая дозировка в мг/сутки рассчитывается
    автоматически (вес × мг/кг схемы), с возможностью ручной корректировки
  - Рядом с расчётом форма показывает список всех справочных вариантов
    кумулятивной дозы этого препарата (если они заданы): для каждого
    варианта — целевая кумулятивная доза для этого пациента (мг/кг × вес) и
    расчётная длительность курса при текущей суточной дозе (целевая доза ÷
    суточная доза ÷ 7, округление вверх). Это чисто справочная информация
    для ориентира — она ничего не блокирует и не привязана к выбранной схеме
    дозирования
  - Длительность курса (в неделях) врач вводит вручную, ориентируясь на
    справочные варианты кумулятивной дозы выше; по умолчанию предлагается
    небольшое стартовое значение, которое врач корректирует под конкретный
    случай (титрование, переносимость, перерывы в лечении)
  - При построении схемы по неделям врач выбирает: «фиксированная доза на
    весь курс» (все недели получают одинаковую рассчитанную дозировку) или
    «меняется по неделям» (титрование — дозировка на каждую неделю вводится
    вручную перед сохранением назначения). После сохранения дозировка и
    комментарий любой недели редактируются отдельно, недели можно добавлять
    и удалять
  - После расчёта дозировки (мг/сутки) калькулятор позволяет выбрать форму
    выпуска и показывает: сколько единиц (капсул/таблеток) нужно в сутки,
    сколько упаковок нужно в неделю и на весь курс лечения заданной
    длительности — с округлением количества упаковок вверх
  - Назначение/редактирование ухода за кожей — простой список записей
    («средство/процедура» + «инструкция по применению»), не привязанный ни к
    неделе лечения, ни к конкретному назначению препарата; врач добавляет,
    редактирует и удаляет записи в любой момент
  - Загрузка фото пациента врачом — загруженное фото появляется и в карточке
    врача, и на странице пациента (динамика лечения)
  - Уведомление врачу, когда пациент загружает своё фото
  - Генерация/просмотр ссылки для пациента, возможность отозвать токен
- Аналитика/отчёты:
  - Количество пациентов по типу патологии
  - Использование препаратов и дозировок (сводная таблица)
  - Экспорт любой таблицы/отчёта в Excel

## 6. Функциональность — интерфейс пациента

- Доступ по ссылке `/patient/{token}`, без пароля
- Отображение:
  - Текущая неделя лечения
  - Текущая дозировка препарата
  - Текущие рекомендации по уходу за кожей — весь список записей ухода,
    назначенных врачом, отображается целиком (без привязки к неделе лечения)
  - Фото: пациент видит фото, загруженные врачом, и может сам загрузить свои
    фото (например, для отслеживания динамики между визитами) — загруженное
    пациентом фото также появляется в карточке врача
  - (опционально) история предыдущих недель
- Уведомления: при добавлении врачом чего-либо (заметки, назначения препарата,
  ухода) пациент видит уведомление об обновлении на своей странице

## 7. Безопасность и приватность

- Токен доступа пациента — длинный, случайный, неугадываемый (UUID v4 или аналог)
- Возможность отозвать/перевыпустить токен из карточки пациента
- Row Level Security в Supabase — обязательна на всех таблицах с данными пациентов
- Фото пациентов — приватный bucket в Storage, доступ через подписанные URL, а не
  публичные ссылки
- Пациент по токену может добавлять свои фото, но не может редактировать/удалять
  фото, загруженные врачом (разграничение через `uploaded_by` + RLS-политики)

## 8. MVP — минимальный объём для первой версии

1. Картотека пациентов (CRUD)
2. Создание диагноза/истории болезни
3. Справочник препаратов и схем дозирования, расчёт дозировки по весу пациента
4. Создание назначения препарата с разбивкой по неделям
5. Назначение ухода за кожей (список записей на пациента)
6. Пациентская страница по токену (текущая неделя, фото, история)
7. Загрузка фото пациента врачом (видно и врачу, и пациенту)
8. In-app уведомления пациенту о новых заметках/назначениях/уходе
9. Экспорт таблицы пациентов/назначений в Excel

## 9. Вне рамок MVP (следующие итерации)

- Несколько врачей / мультиклиника
- Полноценная аналитика/дашборды
- Email/SMS-уведомления (в MVP — только in-app)
- История изменений назначений (аудит)
