# Спецификация: приложение для назначения лечения при кожных заболеваниях

## 1. Назначение

Веб-приложение для врача-дерматолога. Врач ведёт картотеку пациентов, рассчитывает
и назначает схему лечения препаратом и уход за кожей. Пациент по персональной
ссылке видит текущую неделю лечения: какую дозировку принимать сейчас и какой
уход использовать.

## 2. Пользователи

- **Врач** — на старте один пользователь (сам разработчик/владелец), архитектура
  должна допускать расширение на нескольких врачей/клинику в будущем без
  переписывания модели данных (у каждой записи пациента должен быть `doctor_id`).
- **Пациент** — доступ без регистрации и пароля, по уникальной непредсказуемой
  ссылке/токену вида `/patient/{token}`. Доступ только к своей карточке.

## 3. Стек

- **Frontend**: React + Vite, роутинг по ролям (`/doctor/*`, `/patient/:token`)
- **Backend-as-a-service**: Supabase
  - Postgres — данные пациентов, диагнозов, назначений, схем ухода
  - Storage — фото пациентов (например, для отслеживания динамики кожи)
  - Row Level Security — пациент видит только свою запись по токену; врач видит
    только своих пациентов (`doctor_id`)
- **Хостинг фронтенда**: репозиторий на GitHub, деплой на GitHub Pages
  (Vercel не используем — частично заблокирован в РФ, риск нестабильного
  доступа для пациентов)
- **Экспорт данных**: выгрузка таблиц в Excel/CSV — либо через встроенный экспорт
  Supabase, либо кнопкой в интерфейсе врача (SheetJS)

## 4. Модель данных (черновая)

### `doctors`
- id, name, email

### `patients`
- id, doctor_id, full_name, дата рождения, контактные данные
- access_token (уникальный, непредсказуемый — для ссылки пациента)
- дата создания карточки

### `diagnoses` (история болезни пациента)
- id, patient_id, тип патологии/диагноз, дата постановки, заметки врача

### `drugs` (справочник препаратов)
- id, doctor_id, название препарата

### `dosage_rules` (правила дозирования препарата — задаются один раз врачом)
- id, drug_id, степень тяжести (лёгкая/средняя/тяжёлая), дозировка на кг веса (мг/кг)

### `prescriptions` (назначения — расчёт лечения препаратом)
- id, patient_id, diagnosis_id, drug_id
- вес пациента, степень тяжести — выбираются в карточке пациента
- итоговая дозировка — рассчитывается автоматически по `dosage_rules` (вес × мг/кг),
  с возможностью ручной корректировки врачом
- схема по неделям (JSON или отдельная таблица `prescription_weeks`)
- дата начала лечения, статус (активно/завершено)

### `prescription_weeks`
- id, prescription_id, номер недели, дозировка на эту неделю, комментарий

### `skincare_routines` (уход за кожей)
- id, patient_id, prescription_id (опционально), неделя, средства/процедуры, инструкции

### `patient_photos`
- id, patient_id, url (Supabase Storage), дата загрузки, заметка (например "неделя 3")
- uploaded_by (врач/пациент) — определяет права на редактирование/удаление

### `notifications`
- id, patient_id, получатель (врач/пациент), тип (заметка/назначение препарата/
  уход/фото), текст, дата создания, прочитано (да/нет)

## 5. Функциональность — интерфейс врача

- Справочник препаратов и правил дозирования:
  - врач один раз заводит препарат и задаёт правило дозирования по степени
    тяжести (например: аспирин Х — 2 мг/кг при лёгкой, 3 мг/кг при средней,
    4 мг/кг при тяжёлой степени)
  - правила редактируются централизованно, изменение правила не затрагивает
    уже рассчитанные ранее назначения (дозировка фиксируется в `prescriptions`
    на момент расчёта)
- Картотека пациентов: список, поиск, фильтр по патологии/статусу лечения
- Карточка пациента:
  - История болезни (диагнозы, специализированные под кожные заболевания)
  - Текущее и прошлые назначения
  - Форма расчёта нового назначения: врач выбирает препарат, указывает вес
    пациента и степень тяжести — дозировка рассчитывается автоматически по
    сохранённому правилу (с возможностью ручной корректировки), затем
    автоматически строится схема по неделям
  - Назначение/редактирование ухода за кожей по неделям
  - Загрузка фото пациента врачом — загруженное фото появляется и в карточке
    врача, и на странице пациента (динамика лечения)
  - Уведомление врачу, когда пациент загружает своё фото
  - Генерация/просмотр ссылки для пациента, возможность отозвать токен
- Аналитика/отчёты:
  - Количество пациентов по типу патологии
  - Использование препаратов и дозировок (сводная таблица)
  - Экспорт любой таблицы/отчёта в Excel

## 6. Функциональность — интерфейс пациента

- Доступ по ссылке `/patient/{token}`, без пароля
- Отображение:
  - Текущая неделя лечения
  - Текущая дозировка препарата
  - Текущие рекомендации по уходу за кожей
  - Фото: пациент видит фото, загруженные врачом, и может сам загрузить свои
    фото (например, для отслеживания динамики между визитами) — загруженное
    пациентом фото также появляется в карточке врача
  - (опционально) история предыдущих недель
- Уведомления: при добавлении врачом чего-либо (заметки, назначения препарата,
  ухода) пациент видит уведомление об обновлении на своей странице

## 7. Безопасность и приватность

- Токен доступа пациента — длинный, случайный, неугадываемый (UUID v4 или аналог)
- Возможность отозвать/перевыпустить токен из карточки пациента
- Row Level Security в Supabase — обязательна на всех таблицах с данными пациентов
- Фото пациентов — приватный bucket в Storage, доступ через подписанные URL, а не
  публичные ссылки
- Пациент по токену может добавлять свои фото, но не может редактировать/удалять
  фото, загруженные врачом (разграничение через `uploaded_by` + RLS-политики)

## 8. MVP — минимальный объём для первой версии

1. Картотека пациентов (CRUD)
2. Создание диагноза/истории болезни
3. Справочник препаратов и правил дозирования, расчёт дозировки по весу/тяжести
4. Создание назначения препарата с разбивкой по неделям
5. Назначение ухода за кожей по неделям
6. Пациентская страница по токену (текущая неделя, фото, история)
7. Загрузка фото пациента врачом (видно и врачу, и пациенту)
8. In-app уведомления пациенту о новых заметках/назначениях/уходе
9. Экспорт таблицы пациентов/назначений в Excel

## 9. Вне рамок MVP (следующие итерации)

- Несколько врачей / мультиклиника
- Полноценная аналитика/дашборды
- Email/SMS-уведомления (в MVP — только in-app)
- История изменений назначений (аудит)
